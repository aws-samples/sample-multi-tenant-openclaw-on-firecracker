# 解决方案概述

OpenClaw on Firecracker 多租户 AI Agent 平台可帮助您在 AWS 上为成千上万的租户各自交付一台独立内核的轻量虚拟机，在其中运行带身份、技能与安全护栏的 OpenClaw AI agent。该解决方案用 Firecracker microVM 把"越权止于单租户"从容器级别提升到虚拟机级别，并叠加从内容层到凭据层的五层纵深防护，面向需要承载大规模 AI agent、且对租户隔离与性能都有强要求的场景。

该解决方案利用 Amazon EC2 裸金属实例上的原生 KVM 运行 Firecracker microVM，并由无服务器控制面（AWS Lambda、Amazon DynamoDB、Amazon API Gateway）管理租户的注册、生命周期、备份与注销，提供以下能力：

- 为每个租户预配一台独立内核的 Firecracker microVM，在虚拟机级别隔离租户之间的内存、CPU 与内核。
- 将身份、技能、配置在虚拟机启动前冷注入到只读黄金镜像，虚拟机启动即为成品，运行后控制面不向其注入任何业务数据。
- 通过自建 WebSocket 中枢（claw-hub）将浏览器或前端的实时聊天请求按租户路由到对应虚拟机内的 OpenClaw agent。
- 以 Amazon Cognito 作为唯一身份信任根，对控制面与数据面的所有访问统一验签，验签失败一律降级到最小权限。
- 叠加五层纵深防护：内容层、工具执行层、身份层、网络层、凭据与只读监控层，每一层都落实到部署代码或设备，不依赖模型自律。

本实施指南概述了 OpenClaw on Firecracker 多租户 AI Agent 平台解决方案的参考架构与组件、部署规划注意事项，以及将该解决方案部署到 Amazon Web Services (AWS) 云的配置步骤。它面向在 AWS 云中具有架构实践经验的平台工程师、安全评审人员、运维工程师与应用开发人员。

> **Note**
>
> 该解决方案的平台核心与具体业务解耦。控制面、数据面与宿主生命周期脚本不包含任何业务内容，只负责"预配并管理大规模隔离的 AI agent microVM"。每台虚拟机运行什么 agent，由一个可替换的"样本"决定：构建脚本通过 `SAMPLE` 环境变量选择样本，默认 `finance-agent`。随仓库发布的 `finance-agent` 是一个最小骨架样本（身份人设 + 标配安全护栏 + 一个 `weather` 演示技能），具体业务能力由部署方按自身场景在样本目录内填充，平台核心与安全层不随之改变。

## 功能

该解决方案提供以下功能。

**虚拟机级租户隔离**

该解决方案为每个租户预配一台独立内核的 Firecracker microVM，在硬件辅助虚拟化层面隔离租户的内存与 CPU，使单个租户内的越权或逃逸止步于该租户自己的虚拟机，不波及其他租户或宿主。

**启动即成品的冷注入交付**

该解决方案将身份、技能、护栏与配置在虚拟机启动前冷注入到只读黄金镜像盘，虚拟机启动即带完整身份与护栏。运行后控制面不向虚拟机注入任何业务数据，修改身份或技能需重新构建镜像，而非热改运行中的虚拟机。

**五层纵深安全防护**

该解决方案叠加内容层（Amazon Bedrock Guardrails）、工具执行层（agent 进程内护栏）、身份层（Amazon Cognito 验签与基于角色的访问控制）、网络层（宿主 iptables 与 DNS 防火墙）、凭据与只读监控层五层防护，每一层都落实到部署代码或设备。

**统一身份信任根**

该解决方案以 Amazon Cognito 作为唯一身份信任根，控制面与数据面均只接受 Cognito 签发并验签通过的令牌。外部身份提供方通过 OpenID Connect (OIDC) 联合进同一个 Cognito 用户池，对数据面透明。

**无服务器控制面**

该解决方案的注册、生命周期、健康检查、备份、扩缩容逻辑由 AWS Lambda、Amazon DynamoDB 与 Amazon API Gateway 承载，按用量付费，无需运维专用服务器。

**实时聊天中枢**

该解决方案通过自建 WebSocket 中枢（claw-hub）承载浏览器与 agent 之间的实时聊天。虚拟机内的通道客户端主动向中枢拨出连接，不在虚拟机上开放任何入站端口。

**可替换的业务样本**

该解决方案的平台核心与业务样本分层。更换业务场景只需替换样本目录，控制面、隔离机制、安全层与运维工具均不变。

## 优势

该解决方案具有以下优势。

**更强的租户隔离边界**

与共享内核的容器多租户相比，独立内核的 microVM 把隔离边界下沉到虚拟机级别，缩小了横向移动与逃逸的攻击面。

**防御不依赖模型自律**

该解决方案的每一层防护都落实到部署代码或设备：工具执行层在工具真正执行前否决危险动作，网络层在宿主 iptables 上丢弃跨租户流量，即便提示词注入绕过模型，敏感操作仍被拦截。

**配置变更可审计、可回滚**

该解决方案遵循"改部署代码再重建"的纪律，身份、技能、配置的变更随镜像重建继承，可灰度、可回滚，运行后不开放宿主到虚拟机的热注入通道。

**按用量付费的弹性容量**

该解决方案的宿主由 Amazon EC2 Auto Scaling 管理弹性伸缩，控制面采用无服务器服务，容量随负载扩缩。

**实测验证的性能与安全结论**

该解决方案的关键性能、容量与安全结论均有一手实测来源（参见架构详情与规划部署），未实测确认的项在对应章节如实标注为"待核"。

## 使用案例

**大规模 AI agent 托管**

为成千上万的终端用户或租户各自托管一个隔离的 AI agent 实例，并对它们做统一的生命周期与资源管理。

**对隔离强度有合规要求的多租户场景**

在金融等对租户隔离与数据残留有强要求的行业，用虚拟机级隔离满足"单租户越权不外溢"的合规预期。

**面向终端用户的 AI 助手自助开通**

允许已登录的终端用户为自己开通 AI agent 节点，由平台按每用户配额与授权策略门控。

**带安全护栏的 agent 平台交付**

向需要内置越狱拦截、恶意技能拦截、凭据外泄拦截的客户交付一套开箱即带护栏的 agent 平台，并以可替换样本承载具体业务能力。

## 概念和定义

本节介绍此解决方案特有的重要概念与术语。完整术语见本指南的术语表。

**租户（Tenant）**

该解决方案隔离与计费的基本单位。每个租户对应一台 Firecracker microVM，由唯一的 `tenant_id` 标识。

**microVM**

由 Firecracker 在 KVM 之上启动的轻量虚拟机，具备独立内核、毫秒级启动、强隔离特性。该解决方案为每个租户预配一台 microVM。

**冷注入（Cold injection）**

在虚拟机启动前将身份、技能、凭据、配置写入磁盘的过程，与运行后的"热注入/热改"相对。该解决方案的所有身份与配置变更均走冷注入，运行后不热改虚拟机。

**只读黄金镜像（Read-only golden image）**

烤入身份文件与权威技能的只读镜像盘，以 Firecracker 的写屏障、guest 只读挂载、只读绑定三层叠加保证 agent 在虚拟机内无法篡改身份。

**控制面（Control plane）**

由 AWS Lambda、Amazon DynamoDB、Amazon API Gateway 构成的管理平面，负责租户注册、生命周期、备份、注销，运行后不向虚拟机注入业务数据。

**数据面（Data plane）**

由自建 WebSocket 中枢 claw-hub 构成的实时聊天链路，将浏览器请求按租户路由到对应虚拟机内的 agent。

**纵深防护五层（Defense in depth）**

该解决方案的安全模型，自外向内为内容层、工具执行层、身份层、网络层、凭据与只读监控层，每层独立生效、互为正交。

**样本（Sample）**

承载具体业务能力的可替换目录。平台核心与样本分层，更换样本即更换整套 agent 能力，控制面不变。

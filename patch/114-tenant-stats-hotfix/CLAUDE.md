# Claude patch executor: tenant statistics hotfix

This file applies only inside this patch directory. Your job is to discover the
actual target, generate the three exact patch kits, review every generated byte,
and run the fixed driver. Do not improvise AWS write commands.

## Hard Rules

- Read `APPLY-INSTRUCTIONS.md` before running anything.
- Never commit `build/`, `environment.json`, decisions, receipts, logs, account
  ids, API ids, host ids, or credentials.
- Discovery and planning are read-only. Do not apply when the API, stage, Lambda,
  account, or region is unresolved.
- Run only the generated `runtime/scripts/patch-set.sh`. Never invoke or edit
  `lib/compiled/*` directly.
- Never run CDK, setup, or CloudFormation deployment commands for this hotfix.
- Never edit a generated kit after review. One changed byte invalidates its
  review receipt.
- A timeout is unknown, not proof of failure. Inspect the recorded operation,
  wait for a terminal result, then rerun the same fixed command.

## Complete Workflow

1. Get the region and the real configured control-plane base URL from the
   operator. Authenticated probe headers belong in a local JSON file outside Git.
2. Export `OC_CONTROL_PLANE_URL`. When needed, also export
   `OC_CONTROL_PLANE_API_ID`, `OC_CONTROL_PLANE_STAGE`,
   `OC_API_FUNCTION_NAME`, `OC_API_FUNCTION_QUALIFIER`, and
   `OC_CONTROL_PLANE_PROBE_HEADERS_FILE`.
3. Generate and independently review all three target-bound kits:

   ```bash
   bash factory/scripts/prepare.sh "$AWS_REGION"
   ```

4. Read the complete discovery confirmation and all three `CLAUDE-REVIEW.txt`
   files. Stop on any unresolved identity, failed review, or score below 6.5.
5. Generate the plans with the packaged `patch-plan.sh`, read them, then collect
   one set of explicit answers with `interview-once.py`.
6. Apply in this strict order:

   1. `114-tenant-stats-table`
   2. `114-api-lambda`
   3. `114-tenants-stats-route`

   The Lambda reads the new table. The API route must not receive traffic before
   that code and table are live.
7. Invoke the first kit's packaged set driver. Completion requires
   `SET_COMPLETE`, which includes independent verify and a real second run that
   reports `SKIP` with zero writes.
8. Report the source commits, three reviewed fingerprints, environment hash,
   commands, exit codes, receipts, and every skipped or unverified check.

Do not claim completion from a successful first apply, a green syntax check, or
the patch-set ledger alone. The live verify and second fixed-driver run are part
of the patch.
